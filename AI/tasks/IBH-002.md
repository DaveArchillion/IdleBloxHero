## Objective

Create the first scalable, data-driven static-definition layer for Idle Blox Hero.

Establish `Shared/Data` as the canonical static-definition layer with a centralized
read-only DataRegistry.

## Scope

### In Scope

- `Shared/Data` directory structure
- Rarity definition category with one RarityDefinition
- Hero definition category with one HeroDefinition
- Enemy definition category with one EnemyDefinition
- Centralized DataRegistry with deterministic unknown-id error behavior
- Luau type definitions per category
- DefinitionId as string key (separate from runtime EntityId)

### Out of Scope

- combat
- inventory
- persistence / DataStore
- economy
- UI / monetization
- chest / crafting / enhancement / missions / marketplace
- any gameplay system
- Knit / Fusion / Roact / ProfileService

## Architecture Constraints

- Server authoritative
- Shared must not depend on ServerScriptService
- No circular dependencies
- No God modules
- Static definitions contain static data only — no mutable runtime state
- No EntityId inside static definitions
- DefinitionId is separate from runtime EntityId
- DataRegistry is read-only — no write methods exposed
- Definition records and category maps are frozen before being returned
